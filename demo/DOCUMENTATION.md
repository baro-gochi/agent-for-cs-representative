## 시스템 개요

### 목적
신입 상담원이 고객 상담 요약을 입력하면, 관련 약관을 검색하여 **이해하기 쉽게 정리된 안내문**을 제공

### 주요 변경사항
- **기존**: 검색된 약관 원문을 그대로 출력 → 숙련자만 활용 가능
- **신규**: AI가 약관을 분석하여 신입 상담원이 바로 활용할 수 있는 형태로 재구성

### LangGraph 구조
```
상담 요약 입력 
    ↓
키워드 추출 (gpt-5-nano)
    ↓
Vector DB 검색
    ↓
정보 재구성 (gpt-5-mini)
    ↓
신입 상담원용 가이드 출력
```

## 모델 선택 및 비용 분석

### 사용 모델

| 작업 | 모델 | 입력 비용 | 출력 비용 | 선택 이유 |
|------|------|----------|----------|-----------|
| 키워드 추출 | **gpt-5-nano** | $0.050/1M토큰 | $0.400/1M토큰 | 가장 저렴, 간단한 키워드 추출에 충분 |
| 정보 정리 | **gpt-5-mini** | $0.250/1M토큰 | $2.000/1M토큰 | 분석 능력 우수하면서도 비용 효율적 |

### 다른 모델과의 비교

| 모델 | 입력 비용 | 출력 비용 | 적합성 | 비고 |
|------|----------|----------|--------|------|
| gpt-5-nano | $0.050 | $0.400 | ✅ 키워드 추출용 | 가장 경제적 |
| gpt-5-mini | $0.250 | $2.000 | ✅ 정보 정리용 | 비용-성능 최적 |
| gpt-5 | $1.250 | $10.000 | ❌ | 과도한 비용, 불필요한 성능 |
| gpt-4.1-nano | $0.200 | $0.800 | △ | nano보다 4배 비쌈 |
| gpt-4.1-mini | $0.800 | $3.200 | △ | mini보다 3배 비쌈 |

### 모델 선택 근거

#### gpt-5-nano (키워드 추출)
- **작업 특성**: 상담 요약 → 3~5개 키워드 추출 (단순 작업)
- **필요 능력**: 텍스트 이해 + 핵심어 추출
- **출력 길이**: ~20토큰
- **결론**: 가장 저렴한 모델로 충분

#### gpt-5-mini (정보 정리)
- **작업 특성**: 복잡한 약관 문서 분석 + 신입 상담원용 재구성
- **필요 능력**: 문서 이해 + 논리적 정리 + 자연스러운 문장 생성
- **출력 길이**: ~600토큰
- **결론**: 분석 능력 필요하지만 gpt-5는 과도 → mini가 최적

## 하이퍼파라미터 조정 가이드

### 1. Temperature (온도)
**역할**: 응답의 창의성과 일관성을 조절

#### GPT-5-NANO (키워드 추출용)
```python
llm = ChatOpenAI(
    model="gpt-5-nano",
    temperature=0  # 현재 설정
)
```

| 값 | 효과 | 권장 여부 | 사용 상황 |
|---|------|----------|----------|
| 0.0 | 매번 동일한 키워드 추출 | ✅ 권장 | 기본값 (일관성 중요) |
| 0.1-0.3 | 약간의 변화 허용 | △ | 다양한 표현 필요 시 |
| 0.5+ | 일관성 없는 키워드 | ❌ | 사용 금지 |

**추천**: `temperature=0` 유지 (키워드는 일관성이 핵심)

#### GPT-5-MINI (정보 정리용)
```python
llm = ChatOpenAI(
    model="gpt-5-mini",
    temperature=0.3  # 현재 설정
)
```

| 값 | 효과 | 권장 여부 | 예상 결과 |
|---|------|----------|----------|
| 0.0 | 매우 형식적이고 일관된 답변 | △ | 로봇같은 응답 |
| 0.3 | 적절한 창의성, 자연스러운 문장 | ✅ 권장 | 신입 상담원이 읽기 편한 톤 |
| 0.5 | 다양한 표현, 때때로 예상 밖 | △ | 창의적이지만 일관성 떨어짐 |
| 0.7+ | 과도하게 창의적 | ❌ | 예측 불가능, 신뢰도 하락 |

**추천**: `temperature=0.3~0.5` (상황에 따라 조정)

---

### 2. Max Tokens (최대 토큰)
**역할**: 생성할 최대 텍스트 길이 제어 (1토큰 ≈ 한글 1자)

#### GPT-5-NANO (키워드 추출용)
```python
max_tokens=100  # 현재 설정
```

| 값 | 효과 | 권장 여부 |
|---|------|----------|
| 50-100 | 키워드만 추출 | ✅ 권장 |
| 200+ | 불필요한 설명 포함 | ❌ |

**추천**: `max_tokens=100` 유지

#### GPT-5-MINI (정보 정리용)
```python
max_tokens=800  # 현재 설정
```

| 값 | 사용 상황 | 프롬프트 버전 | 예상 출력 길이 |
|---|----------|--------------|---------------|
| 300-500 | 빠른 응답, 간결한 안내 | VERSION 1 | ~400토큰 (200자) |
| 600-800 | 상세한 안내 (기본) | VERSION 2 | ~700토큰 (350자) |
| 1000+ | 매우 상세한 단계별 가이드 | VERSION 3 | ~900토큰 (450자) |

**추천**: 
- 간결형: `max_tokens=400`
- 상세형: `max_tokens=800` ✅ (기본)
- 단계별: `max_tokens=1000`

---

### 3. Top P (누적 확률) - GPT-5 시리즈 미지원 ⚠️
**역할**: 토큰 선택 다양성 조절

#### 중요: GPT-5 모델 (gpt-5-nano, gpt-5-mini, gpt-5) 미지원
```python
# ❌ 오류 발생
top_p=0.9  # BadRequestError: 'top_p' is not supported

# ✅ 올바른 사용
# top_p 파라미터를 제거하고 temperature만 사용
```

**GPT-5 시리즈 특징**:
- `top_p` 파라미터 미지원
- `temperature`로 다양성 조절
- 내부적으로 최적화된 토큰 선택 메커니즘 사용

**대안**: Temperature 값 조정으로 다양성 제어

---

### 4. Frequency Penalty (빈도 페널티)
**역할**: 반복 표현 억제

```python
llm = ChatOpenAI(
    model="gpt-5-mini",
    frequency_penalty=0  # 기본값 (미설정)
)
```

| 값 | 효과 | 권장 여부 | 사용 상황 |
|---|------|----------|----------|
| 0.0 | 반복 허용 | ✅ 기본값 | 자연스러운 문장 |
| 0.3-0.5 | 적절한 반복 억제 | △ | 같은 단어 반복 시 |
| 1.0+ | 과도한 억제 | ❌ | 부자연스러운 문장 |

**추천**: 기본값 유지 또는 `0.3` 설정 (반복이 심할 경우)

---

### 5. Presence Penalty (존재 페널티)
**역할**: 새로운 주제 도입 장려

```python
llm = ChatOpenAI(
    model="gpt-5-mini",
    presence_penalty=0  # 기본값 (미설정)
)
```

| 값 | 효과 | 권장 여부 | 사용 상황 |
|---|------|----------|----------|
| 0.0 | 주제 유지 | ✅ 권장 | 약관 내용에만 집중 |
| 0.5+ | 새로운 주제 도입 | ❌ | 일관성 떨어짐, 약관 벗어남 |

**추천**: 기본값 `0.0` 유지 (약관 범위 내 응답 필요)

## 프롬프트 버전 가이드

### VERSION 1: 간결형

#### 사용 시기
- 빠른 응답이 필요한 경우
- 숙련 상담원 보조
- 간단한 문의 (예: 요금 문의, 단순 해지)

#### 장점
- 짧고 명확
- 토큰 사용량 적음 (비용 절감)
- 빠른 응답 시간

#### 단점
- 세부사항 부족
- 예외상황 안내 미흡
- 신입 상담원에게는 정보 부족 가능

#### 출력 형식
```
1. 핵심 내용 (1-2문장)
2. 고객 안내 멘트
3. 참고 약관
```

#### 예상 출력 길이
- 200-300 토큰 (~150자)

#### 예시
```
1. 핵심 내용
2년 약정 중 1년 경과 후 해지 시 남은 12개월분 위약금 발생

2. 고객 안내 멘트
"남은 약정 기간 12개월의 월 이용료를 곱한 금액이 위약금입니다."

3. 참고 약관
KT 인터넷 이용약관 제15조 (위약금)
```

### VERSION 2: 상세형 (기본) ✅

#### 사용 시기
- 신입 상담원 지원 (기본)
- 복잡한 상담
- 다양한 조건이 있는 경우

#### 장점
- 자세한 설명
- 예외상황 및 주의사항 포함
- 실수 방지
- 신입 상담원이 이해하기 쉬움

#### 단점
- 응답 시간 증가
- 토큰 사용량 많음

#### 출력 형식
```
1️⃣ 핵심 내용 요약
2️⃣ 고객 안내 스크립트
3️⃣ 주의사항 / 예외조건
4️⃣ 관련 약관 출처
```

#### 예상 출력 길이
- 500-800 토큰 (~350자)

#### 예시
```
1️⃣ **핵심 내용 요약**
고객님의 경우 2년 약정 중 1년이 경과한 시점에서 해지를 원하시는 상황입니다. 
약정 위약금은 (남은 약정 개월 수 × 월 이용료)로 계산되며, 
고객님의 경우 약 12개월분의 월 이용료가 위약금으로 청구될 수 있습니다.

2️⃣ **고객 안내 스크립트**
"고객님, 2년 약정 상품을 1년 사용하신 후 해지하실 경우 
위약금이 발생하게 됩니다. 위약금은 남은 약정 기간인 12개월에 
고객님의 월 이용료를 곱한 금액이 됩니다. 정확한 금액은 
고객님의 요금제를 확인한 후 안내드릴 수 있습니다."

3️⃣ **주의사항 / 예외조건**
- 고객의 정확한 월 이용료 확인 필요
- 프로모션 할인이 적용된 경우 할인 전 금액 기준
- 일부 요금제는 위약금 산정 방식이 다를 수 있음

4️⃣ **관련 약관 출처**
KT 인터넷 서비스 이용약관 제15조 (약정 위약금)
```

### VERSION 3: 단계별 가이드형

#### 사용 시기
- 절차가 복잡한 상담
- 순차적 처리가 필요한 경우 (예: 이전 설치, 변경 절차)
- 신입 상담원 교육용

#### 장점
- 단계별 명확한 지시
- 실수 최소화
- 순서가 중요한 업무에 최적

#### 단점
- 간단한 상담에는 과도함
- 토큰 사용량 가장 많음

#### 출력 형식
```
🔍 상황 분석
📞 상담 진행 순서 (STEP 1, 2, 3...)
⚠️ 주의사항
📋 약관 출처
```

#### 예상 출력 길이
- 600-1000 토큰 (~450자)

#### 예시
```
🔍 **상황 분석**
고객이 원하는 것: 약정 위약금 계산 공식 확인
적용 가능한 약관: 2년 약정 중도 해지 위약금 규정

📞 **상담 진행 순서**
STEP 1: 고객의 현재 요금제와 월 이용료 확인
"고객님, 현재 이용 중이신 요금제가 어떻게 되시나요?"

STEP 2: 위약금 계산 공식 안내
"위약금은 남은 약정 기간 × 월 이용료로 계산됩니다. 
고객님의 경우 12개월 × 월 이용료가 됩니다."

STEP 3: 정확한 금액 안내 및 해지 의사 확인
"정확한 금액을 조회해 드리겠습니다. 해지를 진행하시겠습니까?"

⚠️ **주의사항**
- 프로모션 할인은 위약금 계산에 포함되지 않음
- 일부 요금제는 별도 계산식 적용
- 해지 철회 가능 기간 안내 필수

📋 **약관 출처**
KT 인터넷 서비스 이용약관 제15조
```

## 비용 계산

### 1회 실행당 예상 토큰 사용량

#### 키워드 추출 (gpt-5-nano)
- **입력**: ~50토큰 (상담 요약)
- **출력**: ~20토큰 (키워드 3-5개)

#### 정보 정리 (gpt-5-mini)
- **입력**: ~500토큰 (상담 요약 + 검색된 약관 3개)
- **출력**: ~600토큰 (VERSION 2 기준)

### 비용 계산 (1회 실행)

```
키워드 추출 비용 (gpt-5-nano):
  입력: 50 토큰 × $0.050 / 1,000,000 = $0.0000025
  출력: 20 토큰 × $0.400 / 1,000,000 = $0.0000080
  소계: $0.0000105

정보 정리 비용 (gpt-5-mini):
  입력: 500 토큰 × $0.250 / 1,000,000 = $0.0001250
  출력: 600 토큰 × $2.000 / 1,000,000 = $0.0012000
  소계: $0.0013250

─────────────────────────────────────────
총 비용: 약 $0.00134 (약 1.8원)
```

### 비용 절감 팁

1. **프롬프트 버전 선택**
   - 간단한 문의: VERSION 1 사용
   - 복잡한 문의만 VERSION 2/3 사용

2. **Max Tokens 조정**
   - 필요 이상 길게 설정하지 않기
   - VERSION 2에서 800 → 600으로 조정 시 약 25% 절감
